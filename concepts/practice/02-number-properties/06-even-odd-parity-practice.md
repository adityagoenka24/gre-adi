**Lecture capsule:** [06-even-odd-parity.md](../../02-number-properties/06-even-odd-parity.md)

> Parity questions are classification questions, not calculation questions: odd + odd = even, even x anything = even, zero is even, and division has no parity rule.

Every question below is live in the question bank under the ID shown — the sheet and the portal are the same questions. Attempt a level with the clock running, then check Part C.

## Part C — Worked Solutions

### Q1 · `NUM-EOP-002` — Answer: B

Test each option with the parity table. Use p = 2 and q = 3 to keep it concrete, but the rule is what decides.
A - even + odd = odd. With p = 2, q = 3: 5. False.
B - even x anything = even, so p x q is even. With p = 2, q = 3: 6. True.
C - p + p = even, and even + odd = odd. With p = 2, q = 3: 7. False.
D - odd + odd = even, then even + odd = odd. With q = 3: 9. False.
E - p x q is even, and even + odd = odd. With p = 2, q = 3: 9. False.
Check with a second pair, p = 4 and q = 7: A = 11 odd, B = 28 even, C = 15 odd, D = 21 odd, E = 35 odd. Same verdicts.
Answer: B.

**Trap.** Choosing D on the belief that odd + odd + odd is even. The first two odds do pair up to an even, but the third odd flips it back: 3 + 3 + 3 = 9. Choosing C or E comes from forgetting that adding an odd number always changes parity.

### Q2 · `NUM-EOP-004` — Answer: 1

Step 1 — find the parity of the sum. even + odd = odd, so x + y is odd.
Step 2 — translate parity into a remainder. An odd integer is 2k + 1, so dividing it by 2 leaves remainder 1; an even integer would leave remainder 0.
Check with x = 4, y = 3: 7 divided by 2 is 3 remainder 1. Check with x = 0, y = -5: -5 = 2 x (-3) + 1, remainder 1 again.
Answer: 1.

**Trap.** Answering 0 by treating 'x + y' as a sum of two integers and assuming any such sum is even. The answer is also not 0.5: a remainder is a whole number left over, not the fractional part of the quotient.

### Q3 · `NUM-EOP-008` — Answer: 7

Step 1 — list them. The even integers in the range are -6, -4, -2, 0, 2, 4, 6.
Step 2 — count: that is 7 integers.
Two points decide this question. Zero is even, because 0 = 2 x 0, so it belongs on the list. Negative integers have parity too, so -6, -4 and -2 belong as well.
Check by the endpoint formula: from -6 to 6 the evens are spaced 2 apart, giving (6 - (-6))/2 + 1 = 12/2 + 1 = 7. The extra integer 7 is odd and adds nothing.
Answer: 7.

**Trap.** Answering 6 by skipping 0 as 'neither even nor odd'. Answering 3 by counting only the positive evens 2, 4 and 6 and discarding the negatives, which is the 'not even means positive odd' habit in reverse.

### Q4 · `NUM-EOP-010` — Answer: D

Parity is settled here: a + b is odd and a x b is even. But parity says nothing about SIZE, and the question asks which is larger.
Case 1 — a = 2, b = 3: Quantity A = 5, Quantity B = 6. Quantity B is greater.
Case 2 — a = 0, b = 3: Quantity A = 3, Quantity B = 0. Quantity A is greater.
Two legal choices give opposite verdicts, so the relationship is not determined.
Check that both cases are legal: 2 and 0 are both even integers, 3 is odd, and no positivity was stated anywhere in the question.
Answer: D.

**Trap.** Choosing B after testing only a = 2, b = 3 and concluding that a product beats a sum. Setting a = 0 kills the product while the sum survives, and a = 0 is allowed because 0 is an even integer. Choosing A or B on parity grounds is also wrong: an even number is not automatically larger or smaller than an odd one.

### Q5 · `NUM-EOP-011` — Answer: A, B, D

Step 1 — reduce the expression to a single parity. n^3 has the same parity as n, and n^2 has the same parity as n, so n^3 - n^2 + n has the parity of n - n + n, which is the parity of n.
Step 2 — so the expression is even exactly when n is even. The signs do not matter: subtraction obeys the same parity table as addition.
C - n = 3 is odd. 27 - 9 + 3 = 21, odd. False.
D - n = 4 is even. 64 - 16 + 4 = 52, even. True.
A - n = -2 is even; the minus sign does not change parity. -8 - 4 - 2 = -14, even. True.
B - n = 0 is even, since 0 = 2 x 0. 0 - 0 + 0 = 0, even. True.
E - n = 7 is odd. 343 - 49 + 7 = 301, odd. False.
Check: the three selected values 4, -2 and 0 are exactly the even entries in the list.
Answer: D, C, B.

**Trap.** Skipping C because -2 is negative and skipping D because 0 looks like a special case. Both are even integers: parity is about divisibility by 2, not about sign, and 0 divided by 2 leaves remainder 0. The other slip is treating the three terms as if the minus sign could flip a parity, and then selecting A or E because 'two odds and a subtraction' feels even; subtraction follows the same table as addition, so the expression simply inherits the parity of n.

### Q6 · `NUM-EOP-014` — Answer: C

Every term containing a factor of a is even, because even x anything = even. So each expression reduces to 'even + whatever is left'.
A - a^2 x b is even, b is odd; even + odd = odd. False.
B - a x b is even, b is odd; even + odd = odd. False.
C - a^2 x b is even, a is even; even + even = even. True.
D - a x b is even, b is odd, a is even; even + odd + even = odd. False.
E - a^2 x b^2 is even, b is odd; even + odd = odd. False.
Check with a = 2, b = 3: A = 12 + 3 = 15, B = 6 + 3 = 9, C = 12 + 2 = 14, D = 6 + 3 + 2 = 11, E = 36 + 3 = 39. Only C is even.
Answer: C.

**Trap.** Choosing A or E because squaring feels like it should produce an even result on its own. Squaring never changes parity: b^2 is still odd when b is odd, so a^2 x b + b and a^2 x b^2 + b both end as even + odd = odd. The parity of a sum is decided by the odd terms only.

### Q7 · `NUM-EOP-017` — Answer: B

Step 1 — m - n is even, and a difference is even only when the two terms share a parity. So m and n are both odd or both even.
Step 2 — m x n is even, and a product is odd only when every factor is odd. So m and n are not both odd.
Step 3 — combining the two, m and n are both even. Write m = 2j and n = 2k.
A - m + n = 2j + 2k = 2(j + k), which is even but need not be a multiple of 4: m = 2, n = 4 gives 6. False.
B - m x n = 4jk, which is always a multiple of 4. True.
C - both odd would make m x n odd, which the stem forbids. False.
D - both even makes m + n even, never odd. False.
E - m/2 + n/2 = j + k, and j and k have no forced parity: m = 2, n = 4 gives 1 + 2 = 3, odd. False.
Check with m = 6 and n = 10: m - n = -4 even, m x n = 60 even, and 60 = 4 x 15 is a multiple of 4. Check with m = 2 and n = 4: 8 = 4 x 2. Correct.
Answer: B.

**Trap.** Choosing C stops at the first condition: m - n even does mean m and n share a parity, and 'both odd' is the case students reach for first, but it is killed by m x n being even. Choosing A promotes 'the sum of two evens' to 'a multiple of 4'; 2 + 4 = 6 is the counterexample. Choosing E applies parity rules through division: halving two even numbers says nothing about the parity of the halves, since 2/2 = 1 is odd while 4/2 = 2 is even.

### Q8 · `NUM-EOP-021` — Answer: C

A - even x anything = even, so j x k is even. With j = 3, k = 2: 6. False.
B - j + k = odd + even = odd, and odd + 1 = even. With j = 3, k = 2: 6. False.
C - j^2 is odd (squaring never changes parity) and k^2 is even, so odd + even = odd. With j = 3, k = 2: 9 + 4 = 13. True.
D - j x k is even and k is even, so even + even = even. With j = 3, k = 2: 6 + 2 = 8. False.
E - j + k is odd and j - k is odd, so the product is odd x odd = odd, and adding 1 makes it even. With j = 3, k = 2: 5 x 1 + 1 = 6. False.
Check with j = 5, k = 4: A = 20 even, B = 10 even, C = 25 + 16 = 41 odd, D = 24 even, E = 9 x 1 + 1 = 10 even. Same verdicts.
Answer: C.

**Trap.** Choosing E after correctly finding that (j + k)(j - k) is odd and then ignoring the '+ 1', which flips it to even. Rejecting C is the other slip: squaring does not turn an odd number even, so j^2 + k^2 is odd + even = odd.

### Q9 · `NUM-EOP-022` — Answer: 10

Step 1 — parity check on the sum. a + b = 15 is odd, and even + odd = odd, so the stated parities are consistent.
Step 2 — factor pairs of 50 with a positive integer sum of 15: 1 x 50 sums to 51, 2 x 25 sums to 27, 5 x 10 sums to 15. Only 5 and 10 work.
Step 3 — assign by parity. a is even, so a = 10, and b = 5, which is odd as required.
Check: 10 + 5 = 15 and 10 x 5 = 50, with 10 even and 5 odd. Correct.
Answer: 10.

**Trap.** Answering 5, which is the other member of the pair but the odd one, so it is b, not a. The parity condition in the stem is what tells the two apart; without reading it the pair {5, 10} looks symmetric.

### Q10 · `NUM-EOP-024` — Answer: D

Step 1 — split on the parity of n, because that decides where the factors of 2 sit.
Step 2 — n even. Then n and n + 2 are consecutive even numbers, so one of them is a multiple of 4. The product is therefore a multiple of 4 and the remainder is 0. Example n = 2: 2 x 3 x 4 = 24, and 24/4 = 6 exactly.
Step 3 — n odd. Then n and n + 2 are both odd and the only even factor is n + 1. If n + 1 is a multiple of 4 the remainder is 0; if n + 1 is only a multiple of 2 the product carries exactly one factor of 2 and the remainder is 2. Example n = 3: 3 x 4 x 5 = 60, remainder 0. Example n = 1: 1 x 2 x 3 = 6, and 6 = 4 + 2, remainder 2.
Step 4 — n = 1 gives Quantity A = 2, which is greater than Quantity B, while n = 2 gives Quantity A = 0, which equals Quantity B. Two legal values of n give different verdicts.
Check n = 5: 5 x 6 x 7 = 210, and 210 = 4 x 52 + 2, remainder 2. Check n = 4: 4 x 5 x 6 = 120, remainder 0. Both outcomes really occur.
Answer: D.

**Trap.** Choosing C by carrying over the familiar fact that three consecutive integers always contain an even factor. That pins the remainder on division by 2 at 0, but it does not pin the remainder on division by 4: one factor of 2 is guaranteed, a second is not. Choosing A comes from testing only odd n such as n = 1 and n = 5, both of which give remainder 2, and never trying an even n.

### Q11 · `NUM-EOP-031` — Answer: 10

Step 1 — 6n is 6 times an integer, so it is even for every integer n, positive, negative or zero.
Step 2 — 6n + 3 = even + odd = odd, for every integer n. The condition never fails.
Step 3 — count the integers in the range: from -4 to 5 inclusive there are 5 - (-4) + 1 = 10 integers.
Check the two ends: n = -4 gives 6(-4) + 3 = -21, odd; n = 5 gives 33, odd. Check n = 0: 3, odd.
Answer: 10.

**Trap.** Answering 5 by assuming 6n + 3 is odd only when n is odd, then counting the odd values of n in the range. The coefficient 6 is even, so it wipes out n's parity entirely: the term 6n is even no matter what n is.

### Q12 · `NUM-EOP-032` — Answer: A

Step 1 — a negative base raised to an even exponent gives a positive result: the minus signs pair off. So (-1)^p = 1 for every even p.
Step 2 — a negative base raised to an odd exponent leaves one minus sign unpaired: (-1)^q = -1 for every odd q.
Step 3 — 1 > -1, and this holds for every legal pair, so Quantity A is always greater.
Check p = 2, q = 3: (-1)^2 = 1 and (-1)^3 = -1. Check p = 10, q = 7: 1 and -1 again.
Answer: A.

**Trap.** Choosing D because p and q are unspecified. The actual sizes of p and q never matter; only their parity does, and that is fixed by the stem, so the two columns are locked at 1 and -1. Choosing C comes from reading (-1)^q as -1^q and treating both as 1.

### Q13 · `NUM-EOP-033` — Answer: E

Step 1 — 36 = 2^2 x 3^2, so the odd factors of 36 are the ones built only from 3s: 1, 3 and 9.
Step 2 — pair each with its partner: 1 x 36, 3 x 12, 9 x 4.
Step 3 — the partners available are 36, 12 and 4, so the greatest is 36.
Check: 1 x 36 = 36, and 1 is odd, so the pair is legal. Correct.

**Trap.** Choosing 18 (option D) takes the largest proper factor of 36 and forgets to check its partner: 18 x 2 = 36, but 2 is even, so that pair breaks the condition. Choosing 12 (option C) treats 1 as 'not really a factor' and starts the odd list at 3, giving the partner of 3. Choosing 9 (option B) finds the largest ODD factor of 36 and reports it instead of its partner, answering the wrong half of the pair. Choosing 6 (option A) splits 36 evenly as 6 x 6, the reflex that ignores the requirement that one factor be odd - 6 is even.

### Q14 · `NUM-EOP-035` — Answer: B

Step 1 — read what the parity conditions actually do. m + n odd means one of them is even and the other odd, which already forces mn to be even. The parity information is consistent but adds nothing to the comparison.
Step 2 — factor both columns. Quantity A = mn x m and Quantity B = mn x n, so both are the same positive quantity mn multiplied by m and by n respectively.
Step 3 — m and n are positive, so mn > 0 and dividing both columns by mn is safe. The comparison reduces to m versus n, and the stem says m < n.
Step 4 — therefore m^2 n < m n^2 for every legal pair, so Quantity B is greater.
Check m = 2, n = 3: Quantity A = 4 x 3 = 12, Quantity B = 2 x 9 = 18. Check m = 3, n = 8: Quantity A = 9 x 8 = 72, Quantity B = 3 x 64 = 192. Quantity B wins both.
Answer: B.

**Trap.** Choosing D because the parity conditions look like they might let the columns swap. They cannot: the parity facts are a red herring, and the only thing that decides the comparison is m < n with both positive. Choosing A comes from thinking the squared variable automatically makes its column larger, ignoring that the other column squares the bigger number.

### Q15 · `NUM-EOP-029` — Answer: C

The key identity is that n^2 + n = n(n + 1) is a product of two consecutive integers, so it is always even. The same argument handles the cubes, since n^3 has the same parity as n.
